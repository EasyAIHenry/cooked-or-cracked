Scan the code before you install it

3 min

Free code from the internet can carry anything. Run it through SkillSpector, a free scanner from NVIDIA, or paste the repo link into Claude and ask it to check what the code sends and where. In the version linked below, the one real issue (an out-of-date login library) is already updated.

free scanner, install steps in the README

A high score from a scanner is a reason to read the findings, not to panic. Most flags on this repo were words like "token" in the docs.

2

Make your own private copy on GitHub

2 min

Open the OpenReply version used in the video, click Use this template (or Fork), and set it to Private. Your copy is yours: nobody sees your settings, and it keeps running if the original changes or disappears.

  1. Name it anything, for example openreply.
  2. Choose Private, then Create repository.
  3. This version already includes the Netlify set-up file and the daily jobs, so there is nothing to edit.

3

Neon: the notebook

3 min

Neon is a free database. It writes down every comment, campaign and DM, so nobody gets the same DM twice. In the Neon console, create a project (pick the region closest to you), then click Connect. Leave Connection pooling on and click Copy snippet. That is your DATABASE_URL.

Copy snippet
two versions of the same address

The copied address contains -pooler. Use it as is for the app. For the one-off table set-up on page 13, Claude uses the same address with -pooler removed. Neon's free plan includes 0.5 GB of storage and 100 compute hours a month.

4

Redis: the waiting line

4 min

Instagram allows 750 private replies an hour per account. If two thousand people comment at once, Redis holds the rest in line so nobody gets lost. On Redis Cloud, click New database and pick the free 30 MB plan, which holds well over ten thousand waiting DMs.

open your database
  1. Open the database. Copy the public endpoint and, under Security, the default user password.
  2. Write REDIS_URL as redis://default:PASSWORD@ENDPOINT.
  3. Configuration, Edit, Eviction policy: noeviction, Save. This stops Redis deleting queued DMs if it ever fills up.

5

Resend: the login email

2 min

Your dashboard has no password. To log in, it emails you a link, so only your inbox gets in. Sign up to Resend with the email you will log in with, then open API Keys, click Create API key and copy it with the copy icon.

use the email you will log in with
The one trap here. Without your own domain, Resend's free test sender (onboarding@resend.dev) only delivers to the email your Resend account was made with. Put that same email in ALLOWED_EMAILS. Sign up with one email and log in with another, and the login email never arrives.

6

Netlify: put your dashboard online

5 min

Netlify gives you a free web address, so there is no domain to buy. Instagram, the login emails and your tracked links all point at it.

  1. In Netlify: Add new project, Import an existing project, GitHub, then pick your private copy. The build settings fill themselves in.
  2. Open Site configuration, Environment variables. Add every line from your key sheet you have so far. Leave the three Meta values for step 7.
  3. Click Deploy. Your address looks like https://your-name.netlify.app. Put it in NEXTAUTH_URL and deploy once more.
  4. Open https://your-name.netlify.app/api/health. "database ok" and "redis ok" mean steps 3 to 6 worked. The worker shows as unhealthy until step 8.
sign up, then Add new project
about Netlify's free plan

The free plan runs on limited monthly credits. Each deploy uses some, and so does traffic. If the credits run out, the site pauses until the next month instead of charging you. Deploy only when you change something.

7

The Meta app: the key that links everything

10 min

This is the slow part, and the part people get stuck on. Go slowly and tick each one off.

7a · Create the app

  1. On Meta for Developers, click Create app. Name it, keep your contact email, click Next.
  2. Under use cases, choose All, then tick Manage messaging & content on Instagram. Only this one.
  3. Business portfolio: I don't want to connect a business portfolio yet is fine. Then Next, and Create app. Meta may ask for your Facebook password.
tick only this

7b · Turn on all four permissions

Open Use cases, Customize, then Add all required permissions. Then open Permissions and features and check these four all say Ready for testing: instagram_business_basic, instagram_business_manage_comments, instagram_business_manage_messages, instagram_business_manage_insights.

manage_comments still says + Add: click it
Check this twice. In our set-up, "Add all" skipped manage_comments. Without it, comments never reach your dashboard. Click + Add on any of the four still missing.

7f · Connect the webhook

This is how Instagram tells your dashboard about every comment. Under Configure webhooks, paste your callback URL and your WEBHOOK_VERIFY_TOKEN, then click Verify and save. A green tick means your site answered.

8

The worker, on a free Google server

8 min

The worker is the part that actually sends the DMs. It has to run all day, so it lives on Google Cloud's always-free e2-micro server. Your laptop can be off.

sign up, add your card for the identity check
  1. Create a Google Cloud account at console.cloud.google.com. New accounts also get trial credit.
  2. Install the Google Cloud CLI and run gcloud auth login in your terminal.
  3. Give Claude the worker prompt on page 13. It creates the server and starts the worker as a service that restarts itself.
  4. Open your /api/health page again. worker healthy: true means it is running.

9

Connect Instagram, build a campaign, test it

5 min
  1. Open https://your-name.netlify.app/login, enter your Resend email, click the link in your inbox.
  2. Settings, Connect Instagram, log in to the account you added as tester.
  3. Campaigns, New campaign. Pick a reel, type your keyword, and fill in the parts below.
  • Reply under the comment: two or three short lines, so replies do not look identical.
  • Opening DM with a button, for example "Send me the guide". Instagram only shares follow status after a button tap.
  • Follow requirement (optional): a short message and an "I'm following" button.
  • DM with the link: your link becomes a tracked link, so you can see clicks.
  • Go Live.
the test

From your second account, comment the keyword. Expect a reply under the comment and a DM within seconds. Tap through to the link. Comments from your own account are ignored on purpose.

let Claude do the terminal parts

Three prompts, copy and paste

Open Claude Code inside the folder where you cloned your private copy, and paste these one at a time. Each one asks before anything that costs money.

1 · secrets and settings file (before step 6)Create a .env file for this OpenReply app. Generate NEXTAUTH_SECRET (openssl rand -base64 32), CRON_SECRET, ENCRYPTION_KEY (exactly 64 hex characters, openssl rand -hex 32) and WEBHOOK_VERIFY_TOKEN, and set META_GRAPH_API_VERSION=v25.0 and COMMENT_POLL_INTERVAL_MS=900000. Leave clearly labelled blank lines for every other value in .env.example. Do not print the secrets in the chat.
2 · create the database tables (after step 3)I have pasted my Neon DATABASE_URL into .env. Run the Prisma migrations for this app against the same address with "-pooler" removed from the host, without printing the address. Then run npm run db:generate and tell me if every migration applied.
3 · the worker on Google Cloud (step 8)I am logged in with gcloud. Create a new project, link my billing account, and create one e2-micro VM in us-central1 with Debian 12 and a 20 GB standard disk (all inside Google's always-free tier, no static IP). On it: add 1 GB of swap, install Node 22, copy this repo and my .env to /opt/openreply, run npm ci and npx prisma generate, and run "npm run worker" as a systemd service that restarts on failure and on boot. Then create a budget alert of 2 in my billing currency at 1% and 100%, with credits excluded. Ask me before any step that could cost money.

if something does not work

The six problems, and the fix

The login email never arrivesResend's test sender only emails the address your Resend account uses. Log in with that one, and check it is in ALLOWED_EMAILS. Look in spam.
Comments come in, nothing happensOpen /api/health. If the worker is not healthy, check the Google server is running.
Instagram sends nothing at allThe Meta app is not published, or the webhook fields are not Subscribed (7f, 7g).
"Insufficient developer role" at loginAccept the tester invitation inside Instagram (7c).
DM buttons do nothingAnother DM tool may own the conversation. Remove it in Instagram, Settings, Apps and websites, or turn off its automation for that keyword.
A non-follower got the linkIf Instagram does not answer the follow check in time, the link goes out anyway, so real followers never get stuck. That is by design.

the honest bit

Who this is for, and who it is not for

set this up if

You pay for a DM tool mainly for comment-to-DM. You are happy to spend 30 minutes once. You want your campaigns, logs and links on accounts you control.

stay on a paid tool if

You want zero set-up. You need flows beyond comment-to-DM, like email capture sequences or multi-channel inboxes. You would rather pay than look after six free accounts.

Keep it running

Instagram logins expire after 60 days. The daily job in this version refreshes yours automatically, so leave the Netlify site live. Check /api/health once a week, and keep your budget alert on.
